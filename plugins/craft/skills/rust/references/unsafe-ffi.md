# Unsafe and FFI

`unsafe_code = "deny"` is the house default. A crate that needs `unsafe` opts in
on the one module that holds it, with a reason:

```rust
#![expect(unsafe_code, reason = "raw allocation for the page table")]
```

## When

Three reasons, and nothing else:

- FFI and platform calls.
- A performance need that a benchmark proved.
- An abstraction safe code cannot express.

Look in std and the crates the repo already has first. They hold the audited
`unsafe` already.

## Rules

- `// SAFETY:` directly above every `unsafe` block and every `unsafe impl`,
  saying why the invariants hold here. `/// # Safety` on every
  `pub unsafe fn`, saying what the caller must uphold. Clippy reads both
  (`undocumented_unsafe_blocks`, `missing_safety_doc`), which is why they
  survive the no-comments rule.
- Inside an `unsafe fn`, each unsafe operation still sits in its own block.
  Edition 2024 warns otherwise.
- Keep `unsafe` in the smallest module that can uphold its invariant, behind a
  safe API. The module boundary is the soundness boundary: the fields the
  invariant depends on are private to it.
- **Sound** means no sequence of safe calls can cause undefined behavior. A
  safe function that can is unsound, and unsound code is never acceptable. If
  the invariant cannot be encapsulated, expose an `unsafe fn` and state the
  contract.
- `unsafe` marks possible undefined behavior, not danger. `delete_database()`
  is a safe function.
- A checked accessor may have an `unsafe fn .._unchecked` sibling. Never the
  other way round.
- Never: `transmute` to cast an enum or change a lifetime; `unsafe impl Send`
  or `Sync` to quiet the compiler; a `&mut` to uninitialized memory; reading
  padding bytes.
- Run Miri over every module that contains `unsafe`, and test it with hostile
  inputs.

## In-place initialization

When all-zero bytes are a valid value, allocate zeroed on the heap and never
build the value on the stack (`Box::new_zeroed`, Rust 1.92):

```rust
pub struct Table {
    pub slots: [u64; 1 << 17],
    pub count: u32,
}

pub fn new_table() -> Box<Table> {
    let table = Box::<Table>::new_zeroed();
    // SAFETY: every field of `Table` is an integer or an array of integers,
    // and all-zero bytes are a valid value for each of them.
    unsafe { table.assume_init() }
}
```

When zero is not valid, write each field through a raw place, so no reference
to uninitialized memory ever exists (`Box::new_uninit` and `&raw mut`, Rust
1.82):

```rust
pub fn boxed_header(magic: u32) -> Box<Header> {
    let mut header = Box::<Header>::new_uninit();
    let ptr = header.as_mut_ptr();
    // SAFETY: `ptr` points to an allocation sized and aligned for `Header`;
    // each field is written through a raw place, so no reference to
    // uninitialized memory is created.
    unsafe {
        (&raw mut (*ptr).magic).write(magic);
        (&raw mut (*ptr).length).write(0);
    }
    // SAFETY: both fields were written just above.
    unsafe { header.assume_init() }
}
```

## FFI

- `#[repr(C)]` on every struct that crosses, fixed-width integer types,
  `CString` and `CStr` for strings.
- Allocate and free on the same side. A pointer the other side owns is wrapped
  in a type whose `Drop` hands it back.
- Hand ownership out with `Box::into_raw` and take it back with
  `Box::from_raw`. Never return a pointer into the stack.
- Check for null and turn it into a `Result` or an error code.
- A panic must not unwind into foreign code. Every function Rust exports
  catches it and returns an error. Under `panic = "abort"` the process exits
  instead, which is defined but gives the host nothing to handle.
- Edition 2024 spelling: `unsafe extern "C" { .. }` for imports,
  `#[unsafe(no_mangle)]` on exports. Exported names share one prefix.
- A wrapper around a native handle offers `unsafe fn from_native(..)` and
  `into_native()`, with the contract stated.

```rust
/// # Safety
///
/// `ptr` must be null or point to `len` initialized bytes that nothing writes
/// to during the call.
#[unsafe(no_mangle)]
pub unsafe extern "C" fn acme_checksum(ptr: *const u8, len: usize) -> i64 {
    if ptr.is_null() {
        return CHECKSUM_NULL;
    }
    // SAFETY: `ptr` is not null, and the caller guarantees `len` readable
    // bytes behind it for the length of this call.
    let bytes = unsafe { std::slice::from_raw_parts(ptr, len) };
    std::panic::catch_unwind(|| i64::from(checksum(bytes))).unwrap_or(CHECKSUM_PANICKED)
}
```

## Crate layout

- A `-sys` crate imports a C library: raw declarations only, generated by
  `bindgen` from the headers, with the generated file checked in and a check
  that regenerating it changes nothing.
- A `-ffi` crate exports Rust as a C API. It only translates types and
  signatures.
- The logic lives in a safe core crate with no `repr(C)` pointer fields in its
  types.
- Across a dynamic-library boundary share only `#[repr(C)]` data. No statics,
  thread-locals or `TypeId`: each side has its own copy.
